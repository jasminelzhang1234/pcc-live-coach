# Privacy Policy

Last updated: 2026-10-05

## Summary

| Data type | Where it stays |
|---|---|
| Microphone audio (raw PCM) | Sent to the **configured STT endpoint** over WebSocket for transcription. Default is **Aliyun NLS** streaming. Switch to a self-hosted STT to keep audio fully local. |
| Speech-to-text transcripts | Generated by the configured STT endpoint (default: Aliyun NLS). The transcript text is then forwarded to your LLM endpoint for reply generation. |
| Conversation text sent to LLM | Sent to a **configurable LLM endpoint** over HTTPS (default: MiniMax API). **You can change the endpoint** to any OpenAI-compatible provider — see [Supported LLM providers](#supported-llm-providers) below. For full offline mode, use a local provider (Ollama / LM Studio / vLLM). |
| TTS audio | Generated by **MiniMax T2A API** (configurable endpoint). |
| Persona data | Stored locally in `personas/` directory. |
| Real practice audio | Stored locally in `practice-logs/sessions/` (gitignored). |
| Per-session artifacts (transcript / assessment / tracker analysis) | Stored locally in `practice-logs/sessions/<YYYY-MM-DD>-session-NN/` (gitignored). |

## Detailed handling

### 1. Audio capture

The browser captures microphone audio using the Web Audio API at 16kHz mono PCM. Audio frames are sent over WebSocket to the local backend (`127.0.0.1:8765` by default). The backend then forwards each frame to the **configured STT endpoint** for transcription — by default, **Aliyun NLS** streaming WebSocket. To keep audio fully local, replace the STT endpoint with a self-hosted OpenAI-compatible STT service (planned).

### 2. Speech-to-text (STT)

Speech recognition runs on the **configured STT endpoint** (default: **Aliyun NLS** — Alibaba Cloud 智能语音交互, project type 实时语音识别). Setup credentials are `ALIYUN_ASR_APPKEY` + `ALIYUN_ACCESS_KEY_ID` + `ALIYUN_ACCESS_KEY_SECRET` in `.env`. See [`phase_b/_reports/aliyun-asr-setup-2026-09-06.md`](phase_b/_reports/aliyun-asr-setup-2026-09-06.md) for the registration walkthrough.

Audio frames leave your machine only for the duration of the active STT session and are processed under Aliyun NLS's privacy policy ([aliyun.com](https://www.aliyun.com)). The backend does **not** cache raw audio sent to STT beyond the in-memory buffer needed for the active session (cleared on session end).

**To switch away from Aliyun NLS:** point the STT client at any compatible streaming endpoint that exposes partial results over WebSocket. Self-hosted STT is planned; today, only Aliyun NLS has been validated end-to-end. If you modify the backend to use a different STT, you do so at your own risk and must update this policy accordingly.

### 3. Language model (LLM)

Conversation text is sent to a **language model endpoint** to generate coach responses. The default endpoint is **MiniMax API** (configured via `LLM_API_KEY` and `LLM_BASE_URL` environment variables). MiniMax processes the text under their own privacy policy ([minimaxi.com](https://minimaxi.com)).

**To avoid sending any data to MiniMax:**
- Set `LLM_BASE_URL` to a self-hosted OpenAI-compatible endpoint (e.g., a local Llama, Qwen, or other model).
- Set `LLM_API_KEY` to any non-empty string (the local server will not validate it).

In self-hosted mode, **no conversation leaves your machine**.

#### Supported LLM providers

The LLM endpoint is **fully configurable** via three environment variables (`LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`). The code uses the standard OpenAI Chat Completions API, so **any OpenAI-compatible endpoint** works. Pick by privacy posture:

| Provider | Where text goes | Setup |
|---|---|---|
| **MiniMax API** (default) | MiniMax cloud | Set `LLM_API_KEY` |
| **OpenAI** | OpenAI cloud | Set `LLM_API_KEY` |
| **DeepSeek** | DeepSeek cloud | Set `LLM_API_KEY` |
| **Azure OpenAI** | Azure cloud | Use Azure-specific auth |
| **Ollama** (local) | **Stays on your machine** | Run Ollama on `localhost:11434` |
| **LM Studio** (local) | **Stays on your machine** | Run LM Studio on `localhost:1234` |
| **vLLM** (local) | **Stays on your machine** | Run vLLM on `localhost:8000` |
| **OpenRouter / OneAPI** | Aggregator cloud | Aggregates many providers |

For **fully offline** operation, choose a local provider (Ollama / LM Studio / vLLM). No conversation text leaves your machine.

### 4. Text-to-speech (TTS)

Coach responses are synthesized via the **MiniMax T2A API** (`speech-2.6-hd` by default). The text of each response is sent to MiniMax over HTTPS, and audio is streamed back. MiniMax processes the text under their own privacy policy.

**To avoid sending any data to MiniMax:**
- Use a self-hosted TTS endpoint compatible with the MiniMax T2A WebSocket protocol (planned).
- Or disable voice output entirely (text-only mode).

### 5. Persona library

Personas are Markdown files stored in `personas/`. They are read locally by the coachee agent. They are not transmitted anywhere.

### 6. Real practice session artifacts

Real (non-persona) practice sessions produce these local files:
- `practice-logs/sessions/<YYYY-MM-DD>-session-NN/audio/<session>.mp3` — original audio (never uploaded)
- `practice-logs/sessions/<YYYY-MM-DD>-session-NN/01-<topic>.md` — cleaned transcript (coach-authored)
- `practice-logs/sessions/<YYYY-MM-DD>-session-NN/02-评估.md` — PCC 37-marker assessment
- `progress/tracker-sessions.csv` — single-row-per-session summary for trending analysis

All files are stored on your local disk and are **not** uploaded anywhere by the tool.

### 6.5 User controls (consent, retention, deletion)

**Consent gate (code-enforced):** The browser must send `{"cmd": "consent", "agree": true}` over the WebSocket before the server begins writing audio. Until that message arrives, the server holds the session in an `await_consent` state and discards all incoming audio frames. The consent modal lives in [phase_b/static/index.html](phase_b/static/index.html) (`#page-consent`).

**Automatic retention:** Raw audio files under `practice-logs/sessions/raw/` are deleted after `AUDIO_RETENTION_DAYS` days (default: 30; 0 disables). The sweep runs on server start and via `POST /api/retention/set`. The dialogue JSONL, rhythm JSONL, and tracker CSV are **not** deleted by retention — they contain text-derived metrics, not raw voice, and are needed for the dashboard and trending chart.

**Right-to-delete:** Any session's raw audio can be deleted on demand via `DELETE /api/session/{id}/audio` (idempotent, returns 204). The dialogue / rhythm JSONL rows for that session remain (text-derived metrics, not voice).

**No background recording:** Audio is captured only while the WebSocket is open. Closing the browser tab, ending the session via `{"cmd":"end"}`, or losing the network closes the socket and stops recording immediately.

### 7. Append to tracker CSV

Rhythm features are appended to `progress/tracker-sessions.csv` for the existing analysis pipeline. This file stays local.

### 8. No telemetry

This tool does **not** include telemetry, analytics, crash reporting, or any other outbound data collection. There is no "phone home".

### 9. No cookies, no auth

The tool runs on `127.0.0.1` only (no public exposure by default). There is no user authentication, no cookies, no sessions to manage.

---

> **Note on path and file naming (2026-10-05)**: The directory `practice-logs/sessions/` and the tracker file `progress/tracker-sessions.csv` (formerly `practice-logs/真人练习/` and `progress/tracker-real-sessions.csv`; see [CHANGELOG.md](CHANGELOG.md)) intentionally use neutral, generic names. This avoids leaking "real practice" semantics in cloud-sync paths, backup filenames, error stack traces, and path-aware log aggregation. **The contents are still personal data** — the rename only obscures the path/filename, not the data. All backup-disable / encryption / retention recommendations below still apply.

## What we recommend

If you are practicing with sensitive real client material (which you should generally **avoid** for privacy reasons — use AI personas for practice, real clients for credentialing):

- Run on an air-gapped machine.
- Use a self-hosted LLM and TTS.
- Delete session logs after each session.
- Disable cloud backups of `practice-logs/` (covers both AI persona reports and real-session artifacts) and `progress/`.

---

## Changes to this policy

If the tool's privacy posture changes (e.g., optional cloud feature added), this document will be updated and the change noted in `CHANGELOG.md`.

## 详细说明

### 1. 音频采集

浏览器使用 Web Audio API 以 16kHz 单声道 PCM 采集麦克风音频。音频帧通过 WebSocket 发送到本地后端(默认 `127.0.0.1:8765`)。后端随后把每一帧转发到**可配置的 STT 端点**做转写 —— 默认是 **Aliyun NLS** 流式 WebSocket。要让音频完全留在本地,请把 STT 端点替换为自托管 OpenAI 兼容 STT 服务(计划中)。

### 2. 语音转文字(STT)

语音识别运行在**可配置的 STT 端点**(默认:**Aliyun NLS** —— 阿里云智能语音交互,项目类型"实时语音识别")。注册凭证为 `.env` 中的 `ALIYUN_ASR_APPKEY` + `ALIYUN_ACCESS_KEY_ID` + `ALIYUN_ACCESS_KEY_SECRET`。注册步骤见 [`phase_b/_reports/aliyun-asr-setup-2026-09-06.md`](phase_b/_reports/aliyun-asr-setup-2026-09-06.md)。

音频帧只在当前 STT 会话活跃期间离开你的机器,并按阿里云 NLS 自身的隐私策略处理([aliyun.com](https://www.aliyun.com))。后端**不会**在会话结束后缓存发给 STT 的原始音频(仅保留会话所需的内存缓冲)。

**要切换掉 Aliyun NLS:** 把 STT 客户端指向任意支持 WebSocket 流式 partial 输出的兼容端点。自托管 STT 计划中;目前仅 Aliyun NLS 做过端到端验证。如果你修改后端使用其他 STT,你需自行承担风险,并相应更新本策略。

### 3. 语言模型(LLM)

对话文本被发送到一个**语言模型端点**以生成教练回应。默认端点是 **MiniMax API**(通过 `LLM_API_KEY` 和 `LLM_BASE_URL` 环境变量配置)。MiniMax 按其自己的隐私策略处理文本([minimaxi.com](https://minimaxi.com))。

**要避免向 MiniMax 发送任何数据:**
- 将 `LLM_BASE_URL` 设置为自托管的 OpenAI 兼容端点(例如本地的 Llama、Qwen 或其他模型)
- 将 `LLM_API_KEY` 设置为任意非空字符串(本地服务器不会校验)

在自托管模式下,**所有对话都不离开你的机器**。

#### 支持的 LLM providers

LLM 端点**完全可配置**,通过三个环境变量(`LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL`)控制。代码使用标准 OpenAI Chat Completions API,因此**任何 OpenAI 兼容端点**都可以工作。按隐私姿态选择:

| Provider | 文本去向 | 设置 |
|---|---|---|
| **MiniMax API**(默认) | MiniMax 云端 | 设置 `LLM_API_KEY` |
| **OpenAI** | OpenAI 云端 | 设置 `LLM_API_KEY` |
| **DeepSeek** | DeepSeek 云端 | 设置 `LLM_API_KEY` |
| **Azure OpenAI** | Azure 云端 | 使用 Azure 专用认证 |
| **Ollama**(本地) | **保留在你的机器上** | 在 `localhost:11434` 运行 Ollama |
| **LM Studio**(本地) | **保留在你的机器上** | 在 `localhost:1234` 运行 LM Studio |
| **vLLM**(本地) | **保留在你的机器上** | 在 `localhost:8000` 运行 vLLM |
| **OpenRouter / OneAPI** | 聚合云端 | 聚合多家 provider |

要实现**完全离线**运行,选择本地 provider(Ollama / LM Studio / vLLM)。对话文本不会离开你的机器。

### 4. 语音合成(TTS)

教练回应通过 **MiniMax T2A API**(默认 `speech-2.6-hd`)合成。每条回应的文本通过 HTTPS 发往 MiniMax,音频流式返回。MiniMax 按其自己的隐私策略处理文本。

**要避免向 MiniMax 发送任何数据:**
- 使用与 MiniMax T2A WebSocket 协议兼容的自托管 TTS 端点(计划中)
- 或完全禁用语音输出(仅文字模式)

### 5. 人格库

人格是 Markdown 文件,存储在 `personas/`。它们由陪练 agent 本地读取,不会被传输到任何地方。

### 6. 真人练习会话产物

真人(非 persona)练习会话产生以下本地文件:
- `practice-logs/sessions/<YYYY-MM-DD>-session-NN/audio/<session>.mp3` —— 原始音频(绝不外传)
- `practice-logs/sessions/<YYYY-MM-DD>-session-NN/01-<议题>.md` —— 整理后逐字稿(本人撰写)
- `practice-logs/sessions/<YYYY-MM-DD>-session-NN/02-评估.md` —— PCC 37-marker 评估报告
- `progress/tracker-sessions.csv` —— 逐场摘要,供 trending 分析使用

所有文件存储在你的本地磁盘上。本工具**不会**将它们上传到任何地方。

### 6.5 用户控制(同意、保留、删除)

**同意门(代码强制):** 浏览器必须先通过 WebSocket 发送 `{"cmd": "consent", "agree": true}`,服务端才会开始写入音频。在此之前,服务端让 session 处于 `await_consent` 状态,所有收到的音频帧全部丢弃。同意 modal 在 [phase_b/static/index.html](phase_b/static/index.html) (`#page-consent`)。

**自动保留期:** `practice-logs/sessions/raw/` 下的原始音频在 `AUDIO_RETENTION_DAYS` 天后自动删除(默认 30 天;设为 0 禁用)。sweep 在服务启动时跑一次,也可以通过 `POST /api/retention/set` 主动触发。dialogue JSONL、rhythm JSONL、tracker CSV **不会**被保留期 sweep 删除 —— 它们是文字派生指标,不是原始声音,dashboard 和 trending chart 仍然需要。

**删除权:** 任何场次的原始音频可以随时通过 `DELETE /api/session/{id}/audio` 删除(幂等,返回 204)。该场次的 dialogue / rhythm JSONL 保留(文字派生指标,非声音)。

**无后台录音:** 音频只在 WebSocket 连接存活期间被采集。关闭浏览器 tab、通过 `{"cmd":"end"}` 正常结束、或断网,都会立即关闭 socket 停止录音。

### 7. 追加到 tracker CSV

节奏特征被追加到 `progress/tracker-sessions.csv` 以供现有分析流水线使用。此文件保留在本地。

### 8. 无遥测

本工具**不包含**遥测、分析、崩溃报告或任何其他出站数据收集。**没有"回拨"**。

### 9. 无 cookie,无认证

工具仅在 `127.0.0.1` 运行(默认不对外暴露)。没有用户认证、cookie 或会话管理。

## 我们建议

如果你使用敏感的真实客户材料进行练习(出于隐私考虑,你通常应该**避免**这种情况 —— AI 人格用于练习,真人客户用于认证):

- 在气隙隔离的机器上运行
- 使用自托管 LLM 和 TTS
- 每次会话后删除会话日志
- 禁用 `practice-logs/`(覆盖 AI persona 报告和真人练习产物)和 `progress/` 的云备份
